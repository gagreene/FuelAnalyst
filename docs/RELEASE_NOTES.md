# Release notes

## Unreleased

- Trees Survey123 form version `2026.11.06` adds hidden `sampling_protocol` metadata defaulting to `CWC`, immediately before `tree_large_present`. Republish the form to collect the new field. FuelAnalyst still does not require a protocol column under its default configuration.

- Tree sampling protocol labels now retain literal numeric-looking and NA-like text during CSV, Excel and other supported format reads. Registered labels such as `001` and `NA` no longer lose tree-derived results because of input inference; other columns retain their existing parsing behavior.

- Missing source canopy cover now produces a plot-specific ConPyro Attributes warning naming the configured field. ConPyro skip messages distinguish the canopy-cover density class from trees per hectare and explain missing live species composition. Classification, zero-fill defaults and plot eligibility are unchanged.

- Trees processing now honors explicit absence in `tree_large_present`, `tree_small_present` and `sapling_present`. Absent-class records are skipped with a conflict warning, absent repeats may be omitted when all parents agree, and confirmed empty plots receive zero additive tree totals without synthetic tree records. Blank/missing flags retain legacy behavior.

- Default fire-modelling worker count now falls back to one when the system cannot report its CPU count. Default dictionaries are centralized internally; their documented public import paths are unchanged.

- Tree-derived ConPyro inputs now remain missing for every tree-excluded plot, including plots excluded for unsupported species. Fields such as canopy fuel load, canopy bulk density and conifer percentage previously filled with zero now retain NaN; excluded plots remain ineligible for simulation.
- Fixed pandas 3 dtype handling for empty sapling repeats and blank tree-note columns during crown-base-height cleanup. Fractional DBH normalization and explanatory notes no longer fail on inferred numeric dtypes.

- Added `tree_sampling_params` and public `default_tree_sampling_dict` for global or explicit per-protocol DBH sampling cutoffs. Default measured-tree cutoffs remain 5/12.5 cm. Invalid protocol labels leave the affected plot's tree results missing, log an error and allow other plots to continue; malformed configuration dictionaries still stop the run. Users select the protocol column in their Trees parent table; older exports remain supported without one under the default configuration.

- **Sapling expansion corrected:** Records from the sapling table now use their recorded sapling-plot radius regardless of measured or imputed DBH. Earlier densities, biomass and model inputs can change when a sapling crosses a DBH threshold and the plot radii differ. Measured-tree defaults are unchanged.

## 0.4.0

This is a minor release, not a patch: the vendored ConPyro is refreshed to ConPyro 0.2.0, which renumbers surface models 20 and 21 and corrects the terrain scaling and inputs of other surface models, so their results change. The default surface model (13) and the example results are unchanged. No function signature, dictionary key, or output file name changed.

### Breaking changes and action needed (behaviour and data, not the Python API)

- **Surface rate of spread models other than the default change.** The vendored ConPyro is refreshed to upstream commit `13c497e` (ConPyro 0.2.0). Surface model 20 is now the R wind heuristic (0.2 times the wind speed, in m/min) and the legacy mountain pine beetle curve is model 21: if you set `sros_model` to 20 for the beetle curve, change it to 21. Models 16, 17, and 20 do not support terrain wind adjustment, so a run that selects one of them must set `model_terrain_effects_on_wind` to `False`; otherwise it stops with "Selected surface ROS model has no terrain wind extension". Models 9c, 11c, 18c, and 19 now support terrain wind adjustment (before, selecting one of them with the default settings stopped the run). The slope scaling of model 4 is corrected and the inputs of models 12, 16, 17, and 18c are routed differently, so the results of these models differ from 0.3.0: in calm wind on a 7 percent slope, for example, the surface rate of spread of model 4 is 6 percent lower and that of model 12 is 36 percent lower (upstream's example for model 4 at 40 percent slope, no wind, and 12 percent moisture: 2.92 to 1.38 m/min). The default model (13) is not affected: on the example dataset the fire behaviour, FOFEM mortality, and emissions results equal those of 0.3.0 apart from floating-point differences below 3 parts in a billion, and fire types and severity classes are identical.

### Changes

- `conpyro.input_params.sros_model` accepts every surface model of the refreshed ConPyro: 1 to 4, 9, 11, 12, 13, and 16 to 21, the labels `"9c"`, `"11c"`, `"18c"`, and `"r20"`, or `"use_csv"`. The full list is in `docs/TECHNICAL_REFERENCE.md`.

## 0.3.0

This is a minor release, not a patch: the vendored ConPyro is refreshed so fire behaviour, FOFEM mortality, and emissions results change, and the Survey123 forms change. No function signature, dictionary key, or output file name changed.

### Breaking changes and action needed (behaviour and data, not the Python API)

- **ConPyro fire behaviour results change.** The vendored ConPyro is refreshed to upstream commit `29a2145`, which aligns its equations with the pinned R reference implementation: a corrected crown fire moisture transform and crown spread wiring, new FFMC and surface model coefficients, additional surface and crown models, and new smoothing. No FuelAnalyst function, signature, or column changes, but every `run_conpyro()` result that depends on ConPyro differs from 0.2.0, and so do the FOFEM mortality and emissions results that use it. Two effects explain most of the change. First, active crown fire rate of spread rises about 13 to 15 percent, which raises the crowning criterion, so a fire becomes active crown fire at a wind about 1 to 2 km/h lower than before. Second, the head fire rate of spread (`hros`) is now a probability-weighted blend of the surface and crown rates of spread, so even in a scenario classed as surface fire, `hros` and the fire intensity derived from it (`hfi`) include an expected crown fire contribution; before, a scenario with a crown fire probability below 50 percent took the surface rate. Surface fuel moisture is unchanged (under 0.1 percent). On the example dataset (17 modelled plots, 51,968 weather scenarios) the mean head fire rate of spread rises 24 percent (3.05 to 3.77 m/min), head fire intensity 25 percent (2,387 to 2,993 kW/m), crown rate of spread 17 percent, surface rate of spread 4 percent, and flame length 21 percent; 1.0 percent of the scenarios change fire type, mostly toward more crown fire (active crown fire 812 to 1,175 scenarios, 1.6 to 2.3 percent). The FOFEM results follow: flaming emissions rise about 10 percent, smoldering emissions under 1 percent, and total CO2 3.4 percent (2,508 to 2,594 g/m2), and the crown scorch dead basal area rises about 10 percent (6.21 to 6.82 m2/ha). Rerun `run_conpyro()` on existing data, and do not compare new results with results from 0.2.0 or earlier.
- **Republish the Plot Attributes, Trees, Plants and Regen, and Woody Debris forms** (version `2026.10.28`). Ten species that crews could pick on the Trees form (`CE`, `EG`, `EWT`, `EY`, `MRD`, `MS`, `PE`, `QR`, `QW`, `VL`) had no row in the form's `media/Tree_Types.csv`, which the form uses to look up the tree type and so which decay classes to ask; they are added. The Plants and Regen form and the Woody Debris form also lacked those ten (the Plants and Regen form also lacked `A`); they are added, so the Plot Attributes, Trees, Plants and Regen, and Woody Debris forms offer the same tree species codes. The shrub codes `JD` (common juniper) and `JH` (creeping juniper) are not trees, so they get no tree type and are removed from the Plot Attributes and Trees forms; they stay on the Woody Debris form, where their stems add small-diameter woody fuel, and are not added to the Plants and Regen form. Data already collected with `JD` or `JH` on the old Trees or Plot Attributes forms still runs. `FD` and `PL` stay out of the lists on purpose, because the forms offer the interior and coastal codes (`FDC`, `FDI`, `PLC`, `PLI`). Data from the old forms still runs; the new species can only be chosen after the forms are republished. A new test (`tests/unit/test_survey123_species_lists.py`) checks that the forms and the species tables agree.

### Changes

- `fuel_analyst()` now reports highly decayed trees (decay class 6 or higher for conifers, 5 or higher for broadleaves, with a density above zero) that have no measured height. When the DBH is recorded, the height is modelled from it (as it already was for the biomass equations) and a warning (`decayed_tree_height_modeled`) is written to the Trees column of `fuelanalyst_errors.csv`. A tree with neither a height nor a DBH cannot be modelled and adds no biomass, which is reported as an error (`decayed_tree_not_modellable`), and so is one with a height but no DBH (`decayed_tree_dbh_missing`). Each plot is reported once per issue, with the `tree_id` of every affected tree. No calculation changes.
- `run_conpyro()` with the official FOFEM 6.9.4 emissions engine (`model_select` of `fof_gui`) now reports every plot whose `runfofem.exe` rows failed, whatever the number of workers. Before, the report was written only when fewer than four workers ran, because a log record made inside a worker process never reached the parent. Each plot and cause is logged once (`fofem_gui_emissions_runfofem_failure`), with the number of failed weather scenarios and the first weather date, in the FOFEM 6.9.4 Emissions column of `run_conpyro_errors.csv`, under the original plot ID. The failed rows still hold their `fofem_gui_error` message in the results. No calculation changes.
- `run_conpyro()` now logs each plot it leaves out because `stand_density` or `stand_type` is empty (a plot with no live overstory, or one whose tree calculations were left out because of a species code that is not in `tree_parameters.csv`). The warning (`conpyro_plot_skipped_empty_stand`) is written to the ConPyro Fire Behavior column of `run_conpyro_errors.csv`, with the plot's identity columns. The plots are still left out of the results and the run continues; no calculation changes.

## 0.2.0

This is a minor release, not a patch: the Plants form has a new required question, some results change, and a run that used to stop on an unlisted species now continues without that plot. No function signature, dictionary key, or file name changed.

### Breaking changes and action needed (behaviour and data, not the Python API)

- **Republish the Plants form.** It has a new required question, `pc_species_N_other_group`, asked when a crew selects `OTHER`. An export from an older form, without that column, still runs: an `OTHER` species with no group adds no biomass and is reported. If you use a custom copy of `plant_photoload.csv` with the form, add the `NO_SPP` and `OTHER` rows (the form builds its species choices from the file).
- **Dead `F` and `PE` tree biomass changes.** Conifer status now comes only from the `TreeType` column of `tree_parameters.csv`, so ash (`F`, a broadleaf) uses the broadleaf decay table and eastern white pine (`PE`, a conifer) uses the conifer table. Regenerate any outputs that include dead trees of these species. The module-level `conifer_list` of `trees.py` is removed.
- **Unlisted species no longer stop the run.** A tree or sapling species that is not in `tree_parameters.csv` used to raise a `KeyError`. Now the plot is logged, left out of the tree calculations (empty tree columns, empty stand type and density in `conpyro_df.csv`, no row in the FOFEM consumption file), and the run continues. Read `fuelanalyst_errors.csv` after every run, and do not assume every plot has complete results.
- **The error reports have new columns.** "ConPyro Attributes" appears in `fuelanalyst_errors.csv` and "ConPyro Fire Behavior" in `run_conpyro_errors.csv`, with new issue codes. Code that reads these files by position must allow for the extra columns.

### Changes

- A plant species code that is not in `plant_photoload.csv` (codes are case-sensitive), or whose table entry names a PhotoLoad series without an equation, now prints a warning for each affected plot and is written to the Plants and Regeneration column of `fuelanalyst_errors.csv` (`plant_species_not_in_table`, `plant_species_no_equation`). Before, such a species added no biomass to any functional group and gave no notice. The calculation is unchanged: the species still adds no biomass. `NO_SPP` and empty entries are not reported.
- `plant_photoload.csv` has two new rows that are not species: `NO_SPP` (no further species) and `OTHER` (a species that is not in the list). The Survey123 Plants form builds its species choices from this file. `NO_SPP` now explicitly contributes zero biomass, and any cover or height recorded with it is ignored.
- A species recorded as `OTHER` whose name (`pc_species_N_other`) is not in the table, or that has no name, is now estimated when the crew also chose its functional group (`pc_species_N_other_group`: grass, herb and forb, shrub, or moss and lichen). Its biomass is the average, over all species of that group in `plant_photoload.csv`, of each species' own PhotoLoad equation at the recorded cover and height, and the species counts in the chosen group. Each estimate logs a `plant_species_other_estimated` warning, and adding the species to the table replaces it. A group of mosses and lichens averages to zero. An `OTHER` species with neither a name in the table nor a valid group adds no biomass and is reported (`plant_species_not_in_table`, or `plant_species_other_no_name` when it has no name). An export from an older version of the form, without the group column, still runs and gets the no-biomass warning.
- The Plants form in `docs/survey123/survey123_forms/` has a new required question that asks for the functional group when `OTHER` is selected. Republish the form to give crews the question. The forms folder also has a README and empty `.xml` placeholders that let each form folder open in Survey123 Connect, and a `.gitignore` for the files Connect creates.
- A tree or sapling species that is not in `tree_parameters.csv` no longer stops `fuel_analyst()` with a `KeyError`. Each affected plot is logged in the Trees column of `fuelanalyst_errors.csv` (`tree_species_not_in_table`), every tree and sapling record of that plot is left out of the tree calculations so that no plot is summarized from only some of its trees, and the run continues with the other plots. The plot's tree columns are missing (not 0) in `master_fuel_df.csv`, its stand type and density in `conpyro_df.csv` are empty (so `run_conpyro()` skips it like any plot with no live overstory), and it has no row in the FOFEM consumption file. Only empty entries and `NO_SAPLINGS` are ignored in the sapling table; any other code, including `NO_REGEN`, is looked up like a species.
- A species code in `SPECIES_CD_1` to `SPECIES_CD_6` that is not in `tree_parameters.csv` now logs the plot (`stand_type_species_not_in_table`, in a new ConPyro Attributes column of the error report) and leaves its stand type empty, instead of raising a `KeyError` that named only the first unknown code.
- Conifer status now comes only from the `TreeType` column of `tree_parameters.csv`. The hard-coded `conifer_list` in `trees.py` is removed. The two sources disagreed for two species, and only the dead-tree biomass of those two changes: `F` (ash, a broadleaf) now uses the broadleaf decay table, and `PE` (eastern white pine, a conifer) now uses the conifer table, which has an entry for decay class 9. The example outputs are byte-identical to 0.1.2.
- `run_conpyro()` warns when the CFIS crown fire model (`cfo_model` 10, or a 10 in a `use_csv` column) runs on plots without an FBP fuel type (`cfis_missing_fuel_type`). It also warns for each plot that has a fuel type but loses it, because ConPyro receives the fuel types of a run only when every plot of the same weather date and time has one (`cfis_fuel_type_not_used`). The warnings are written to a new ConPyro Fire Behavior column of `run_conpyro_errors.csv`. No calculation changes.
- Documentation: the README has a new "Updating the species tables" section (also described in `docs/CONTRIBUTION_PROCEDURES.md`), a "Calculation methods" summary of each component, and configuration tables for the woody debris, ConPyro, and FOFEM consumption dictionaries. A new technical reference, `docs/TECHNICAL_REFERENCE.md`, carries the detail: every setting and default, the equations and every output variable, and the ConPyro and FOFEM workflow, with figures. A documentation audit also corrected statements in the README, quick start, test guide, architecture notes, and the docstrings of three example scripts. The tutorial notebook has a new section 7 that rebuilds the tables and figures of the FuelAnalyst paper from the example data. A `No AI attribution` check now runs on every pull request. The license file is renamed from `LICENSE` to `LICENSE.txt` (same MIT text), and `pyproject.toml` lists it under `license-files`.

The example dataset gives byte-identical results to 0.1.2.

## 0.1.2

- `fuel_analyst()` now reads the Excel and file geodatabase downloads of ArcGIS Survey123 and ArcGIS Online as well as CSV, and also GeoPackage, SQLite, GeoJSON, Parquet, and Feather tables. Each form folder can hold CSV, Parquet, Feather, or GeoJSON files (one per table, named like the CSV; a GeoJSON parent table holds points and repeat tables hold features without geometry), one Excel workbook (`.xlsx` or `.xlsm`, one sheet per table), one GeoPackage (`.gpkg`, one layer per table), one plain SQLite database (`.sqlite`, `.sqlite3`, or `.db`, one table per table), or an unzipped `.gdb` folder (one layer per table). The format is detected for each form, and forms can differ. Containers match a table by its full name (`survey_0`) or the name without its number (`survey`). See "Supported file formats" in the README.
- If one form folder holds several formats (unusual), one is used, in this order: CSV, Parquet, Feather, GeoJSON, Excel, GeoPackage, SQLite, geodatabase, and the run prints a note naming the formats it found. Existing CSV inputs behave exactly as before: on the example dataset every output file is byte-identical to 0.1.1.
- Downloads must be unzipped. A form folder that holds only a zip raises an error that says to unzip it. Two workbooks, GeoPackages, SQLite files, or geodatabases that hold the same table raise an error naming both files.
- Tables from the other formats are converted to read like their CSV: the same dtypes and missing-value handling as `pd.read_csv`; dates stay datetimes (SQLite and GeoJSON date text is parsed); a geodatabase or GeoPackage table gets `ObjectID` from an `ObjectID` field or else the layer's object ID, lower-case `GlobalID` and `ParentGlobalID` without braces, and `x` and `y` from point geometry in WGS84 degrees unless the layer already has those fields (a layer in another coordinate system is reprojected to EPSG:4326, a layer with no coordinate system must hold valid longitudes and latitudes, and coordinate noise below 1e-9 degrees snaps to 0). Geodatabase coordinates can differ from CSV values by about 1e-10 degrees, and 32-bit numbers can carry a few more digits than the CSV text.
- With Excel or geodatabase inputs, the processed copies of the input tables that `fuel_analyst()` writes beside the results still use the CSV layout, with dates written as ISO text rather than the original text format. The result tables are the same as for CSV inputs.
- New core dependencies: `openpyxl` (3.1.5 or newer) and `pyogrio` (0.7.2 or newer). They install with the package. Parquet and Feather need the new optional `parquet` extra (`pyarrow` 14.0 or newer; also part of `test` and `all`); without it, reading those tables says how to install it. SQLite uses Python's built-in `sqlite3`.
- Fixed a crash in `gen_conpyro_df()` on pandas 3 when `pyarrow` is installed: the stand-type step compared Arrow-backed string columns with a placeholder object. It now tracks missing values with masks, so the result is unchanged and works with or without `pyarrow`.
- New module `fuel_analyst.components.table_reader` (`FormSource`, `resolve_form_source`, `ensure_form_source`, `form_exists`, `has_table`, `read_table`). The component processors (`process_plot_attributes`, `process_plants_regen`, `process_trees`, `process_canopy_cover`, `process_woody_debris`) accept a `FormSource` as well as a folder path. No existing signature, key, or file name changed.

No action is needed for existing CSV workflows. To use an Excel or geodatabase download, unzip it into the form folder (`1_Plot_Attributes` and so on) beside, or instead of, the CSV files.

## 0.1.1

- The FOFEM consumption file now adds the sound and rotten classes of the 1-hour, 10-hour, and 100-hour woody fuels (`wfl1Hour`, `wfl10Hour`, `wfl100Hour`) with a missing class counted as 0. Before, a plot with only one of the two classes got 0 for the whole class, so `wfl1Hour` was always 0 (no rotten pieces exist in the finest class) and sound mass was lost wherever a plot had no rotten pieces in the 10-hour or 100-hour class. These loads feed the FOFEM consumption and emissions calculations.
- Woody specific gravity now follows the size of the piece or tally class. The `SG_*` columns of `tree_parameters.csv` are breakpoints (0.5, 0.635, 1, 2, 2.54, 3, 4, 5, 6, 7, and 7.62, then the open-ended `SG_7.62+`), and a measured piece or tally class takes the first column whose breakpoint is at or above its diameter: greater than the previous breakpoint and up to its own. Before, overlapping ranges overwrote each other, so every measured piece took its value from the US columns whatever the protocol. The `SG_7+` column was removed (its values matched `SG_7.62` and `SG_7.62+`), and the coarse-size values for some species were corrected so that no species gains specific gravity at 7.62 cm or above over its 7 cm value. The plot-level `woody_sg_gt7cm` column is no longer written. A tally class with a custom cutoff (for example, 2.5 cm) now uses the column of the breakpoint at or above it instead of failing for a missing column.
- Tallied fine woody debris is now included in every output class whose range holds the tallied size class, whatever the position of its request in `output_request`. Before, only the first request of a protocol received it, so the default Canadian `woody_kgpm2_can_lt7cm_7` left out the tallied 0.5 cm fines and disagreed with the sum of the Canadian default classes and with ConPyro's `woody_kgpm2_conpyro_lt7cm_7`. A request filtered on a field the tally lacks (such as the FOFEM sound and rotten decay-class requests) still receives the tally only when it is the first request, so the tally is not counted twice. A plot with only a measured or only a tallied mass in a class keeps it instead of becoming missing.
- Flame length and fire intensity are now calculated only for burned plots (a `treatment_type` of `burned`, ignoring case and spaces). Trees of other plots are left missing, a valid tree of a burned plot with no bark char height is recorded as 0, and records without a basal area stay missing. A bark char height recorded on a plot that is not burned is not used and is reported as `char_height_on_unburned_plot` in the Trees column of `fuelanalyst_errors.csv`. When the plot table has no `treatment_type` column, no plot restriction is applied.
- Basal-area-weighted stand means (`ht`, `cbh`, `dcbh`, `fsg`, crown depth, `flame_length`, and `fire_intensity`) now divide by the basal area of the trees that have a value. Before, a tree with a missing value (for example, a dead tree with no crown base height) still added its basal area to the denominator, which biased the mean low, and a plot where no tree had a value got a mean of 0. Those means are now missing. Live-only crown base height and height means are unchanged. Means that include dead trees (for example, the total or conifer summaries of crown base height and the dead crown base height means) increase where dead trees lacked a value, and every `stand_fsg_*` column is missing where no tree has a fuel bed height.
- The default ConPyro fuel strata gap entry (`conpyro_fsg`) now summarizes the crown base height of live conifers (`summary: ['live', 'conifer']`), the same value as `conpyro_cbh_ovrstry`, instead of all conifers. Dead conifers mostly have no crown base height, and their basal area diluted the mean. Set `att_source` to `'fsg'` to use the tree-level fuel strata gap.
- On the example dataset, rerunning `examples/run_fuel_analyst_conpyro_demo.py` after these changes keeps the same 51,968 scenarios across 17 plots. Head fire intensity changes by a median of 0.5%, the fire type changes in 1,121 scenarios (2.2%), and the fire severity class in 598 (1.2%). In the 85th to 95th FWI percentile band of the ten unburned plots, the median head fire intensity of eight plots moves by less than 1%, P15 falls by 7%, and P10 falls by 74%, so its most common fire type changes from passive crown to surface fire; the plots with the largest changes are those whose fuel strata gap input changed most (P10 from 5.71 to 8.51 m). Median CO2 emissions per plot change by -13.8% to +17.5%. The corrected FOFEM 1-hour, 10-hour, and 100-hour woody loads move the median band CO2 from flaming (1.98 to 1.54 kg/m2) toward smoldering (3.88 to 4.08 kg/m2).
- The checked-in example weather-merged file, `examples/data/weather/conpyro_df_wx.csv`, was rebuilt from the corrected plot attributes. Only its `fsg` column (30,570 of 61,139 rows) and `woody_fuel_load` column (every row) changed; the weather observations are untouched.
- `merge_weather_data()` no longer fails with its default settings on a `conpyro_df.csv` that has not been through FBP fuel typing. That file carries `fbp_fuel_type` as an empty placeholder, which a CSV reader returns as floating-point missing values, and the seasonal refinement then applied text operations to it. The column is now read as text in `merge_weather_data()` and in `process_fbp_fuel_type()`, so an empty placeholder is left empty, a partly typed column is refined where it has values, and an existing fuel type is still kept.

Regenerate previously processed woody, tree, ConPyro, and FOFEM outputs where these changes apply. Rebuild weather/plot merges from fresh plot attributes before rerunning fire behaviour and emissions; an existing weather-merged file holds the old `fsg` and `woody_fuel_load` values. A custom copy of `tree_parameters.csv` needs every `SG_*` column named above (`SG_0.5` through `SG_7.62+`); a leftover `SG_7+` column is ignored.

## 0.1.0

- Fuel-bed depth now uses the cover-weighted heights of all usable recorded plant species. Missing species or height observations no longer erase earlier contributions. Empty usable observations remain missing in the plant output.
- Plot canopy cover now averages usable records for transect IDs 1 and 2. A single transect retains its measured percentage; wholly excluded or absent observations do not count as zero cover.
- Duplicate eligible canopy records receive one weight per record rather than summed contributions divided by two. Per-transect diagnostic columns retain their sums; duplicate-heavy inputs can therefore disagree with plot means. No automatic deduplication is performed.
- Tallied woody-debris biomass and both optional QMD comparison masses now convert volume using specific gravity once. Their volume already includes slope-corrected transect length, so the repeated slope multiplier has been removed.
- Woody transect slope correction now uses the exact horizontal projection, `sqrt(1 + (slope_percent / 100)^2)`, instead of squaring the angle in radians. This changes measured and tallied woody loads on sloped plots. The pooled horizontal-length aggregation remains unchanged; flat-transect results are unchanged.
- The consumption CSV still rounds fuel-bed depth to two decimals and replaces missing depth with 0 m. Numeric zero reaches both emissions routes; it does not invoke pyfofem's 0.3 m missing-value fallback. Tree fuel strata gap continues to use the separate field-measured tree fuel-bed height.
- Missing canopy remains missing in the canopy component. The existing ConPyro behavior of exporting zero cover with no density class remains unchanged.
- The checked-in example weather-merged file, `examples/data/weather/conpyro_df_wx.csv`, was rebuilt from the corrected plot attributes. Only its `woody_fuel_load` column changed (by up to 0.0035 kg/m2); the weather observations are untouched. Rerunning `examples/run_fuel_analyst_conpyro_demo.py` on it changes head fire intensity by at most 0.2% and CO2 emissions by at most 0.4% in the 85th to 95th FWI percentile band of the unburned plots, and no fire type or severity class changes.

Regenerate previously processed plant, canopy, woody, ConPyro, and FOFEM outputs where these corrections apply. Rebuild weather/plot merges from fresh plot attributes before rerunning fire behavior and emissions; an existing weather-merged file can contain stale fuel values. Existing weather observations do not need to be re-extracted.
